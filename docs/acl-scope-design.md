# ACL 精确对象与继承隔离实验

日期：2026-10-16。此文是实验设计，不是正式 Plan 或真实权限修改授权。

## 执行边界

Windows 后端和 local-agent 预定以 艺11\hhdn 普通令牌运行。现有 tools/windows-acl.ps1 的参数、执行方式和递归语义本轮不变。新增 tools/windows-acl-scope.ps1 只定义只读函数 Get-SakieAclScope，无写入、Apply、Restore 或自动提权；不注册服务。

调用必须显式给出 DirectTargets 与 ForbiddenTargets，路径必须为存在的本地绝对路径。拒绝卷根、ADS、重解析点及硬链接，路径匹配区分目录边界；读取失败终止，不当作无风险。

## 三种范围与阻断

- direct：明确拟修改的对象；目录目标仅表示直接治理该目录，不意味着批准遍历写入后代。
- potential-inherited：位于直接目录之下，路径上没有保护继承边界的现有对象；Windows 可能间接改变其 ACL。
- outside-propagation：受保护边界及其后代，或单独声明的不相关禁止路径。直接指定对象始终优先分类，不能借保护标志绕过禁止清单。

ForbiddenTargets 对其自身及全部后代生效。任何禁止对象落入 direct/potential-inherited 时 CanProceedToDesignReview=false；这不是执行授权。受保护分支可以在分析上隔离，但新设保护边界本身是权限变更，需要另行审查，原有拒绝夹具不得据此修改。

预测是保守上界，不根据拟设置的 ACE 精确计算最终有效权限，不模拟全部 Windows 继承算法。Allow/Deny、OI/CI、InheritOnly、NoPropagateInherit 可能减少实际改变对象数；工具允许多报，不承诺最终 SDDL。保护边界阻断父级传播并不意味着该分支满足最小权限。没有属性对象 ACE、跨域 SID、SACL、共享权限、父目录删除子项权或硬件故障的完整建模。

## 合成实验证据设计

backend/test/fixtures/acl-scope-lab.ps1 必须接收不存在的新 FixtureRoot，只在该目录下新建合成文件、目录和测试链接；所有 ACL 设置由 PutAcl 核验路径。仅通过现有原生 DACL setter 写测试对象，不请求所有者/SACL权限，不提权。测试不会调用真实工具的 Plan/Apply/Restore，不遍历原有拒绝夹具。

覆盖五个情景：未保护的禁止对象阻断且分析只读；已保护的新测试分支在父根目录治理后 SDDL/所有者保持不变；普通后代实际变化属于预测范围；Allow/Deny、OI/CI/InheritOnly/NoPropagate 的实际传播及未来新建文件；精确文件治理不改变父目录或禁止兄弟分支；链接拒绝。

将新建测试分支设为受保护仅用于证明 Windows 行为，不是对原 z-denied.txt 的修复。保留原拒绝夹具及关联 ACL，不删除或移动。本次实验失败尝试及新夹具亦保留。

## 真实治理仍未就绪

两个 Administrators 所有根目录仍缺当前令牌 WRITE_DAC；不得借原型改变它们。还需审查完整敏感白名单、保留清单、边界建立是否允许、全部直接及潜在影响对象的原始证据、执行身份、并发停止、失败日志与恢复机制。旧 Plan 已失效，不复用。本原型没有正式执行器、可验证回滚或持久审计方案，不能用于真实根目录 Apply。

未来测试应通过 TEST_DATA_ROOT 放到新隔离子树；E 盘根新目录创建被普通权限拒绝时不提权，本轮使用现有 data 目录内全新实验子树，因而真实根目录的对象清单会增加，不能称为物理独立磁盘或已完成存储拆分。

## 换电脑及 SID 变更（仅设计）

目标机器重新识别并确认实际运行 SID，按受审政策重建目标 ACL，不照搬旧 SID 权限、不接管旧账户所有者。旧 SID 仅作为来源审计信息；ACL 计划和现有工具依旧绑定当前 SID，不能自动替换旧计划的 UserSid 或哈希来继续执行。确认管理员/其他服务依赖后才可另行授权移除失效身份。

数据通过一致性备份恢复到新目录并核验完整性；设备重新配对，核对归档代际、云端持久 ACK、连续游标、最后事件证明及事件去重记录。水位落后或证明不符必须停止核对，不重置游标或覆盖原始消息。以上迁移流程本轮未实现或实际验收。

## 本轮实际结果

新增5项测试及原67项回归合计72/72通过，0失败、0跳过；四工作区typecheck/build通过，diff格式检查通过。完整回归约46.7秒。完整回归前后，两份原z-denied.txt的完整SDDL及内容SHA256均一致；现有windows-acl.ps1哈希一致，旧Plan哈希仍为c293b70f1787acec209b8d9f7df23183030aca164e0198f45f0bcf55400d052c。没有真实Apply/Restore、提权或Git提交。

测试过程先发现并修复空冲突集合的PowerShell严格模式问题；合成根权限变更的Set-Acl请求SeSecurityPrivilege后，改用仅DACL原生调用，不提升权限。新实验写入仅发生于新建夹具；测试原有67项中的Plan/Apply/Restore也只针对当次新夹具。

本轮新增测试目录和保留的实验链接/拒绝夹具会改变data对象清单，且全根遍历可能因实验链接而安全拒绝。不要把这个实验目录纳入真实权限治理，也不要自动删除链接或夹具来迎合旧Plan；后续必须明确实验排除边界并审查范围。
