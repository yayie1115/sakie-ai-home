# 目录级 ACL 继承与安全恢复：合成实验

本轮只在新建、完全合成的FixtureRoot内运行，不是生产治理工具。现有windows-acl.ps1、windows-acl-scope.ps1及既有测试语义不变；没有正式生产Plan或真实Apply/Restore。

## 预先独立演练，而非事后接受快照

每项测试创建受测树、独立预演树和三个恢复预演树，均由同一合成配方生成；同一普通用户SID，原始DACL经独立核对。目录含普通后代、深层文件、具有显式Allow/Deny的文件、受保护禁止分支和新的拒绝WRITE_DAC文件。

在受测树进行任何实验变更前，独立预演树执行三步：根目录DACL、子目录DACL、指定文件DACL。记录每步Windows实际传播后的ACL。另对三个可能中断位置分别预演恢复，按父目录在前的顺序回放原始非禁止对象DACL，记录每个恢复步骤的预期ACL，并验证终态与原始ACL等价。

受测树每步必须符合预先演练的模型，文件内容/大小/时间、对象创建时间、对象集合及所有者必须符合原始快照，禁止分支DACL逐字不变。修改后快照只作观测，不可自行成为下一步可信基线。目录保护标志导致派生Class变化时，不能将Class误当文件内容；报告仍以原始范围记录直接/可能影响对象。

这种方法只证明受控同构夹具中的Windows行为，不是任意目录ACL的数学模拟，不保证生产环境可复现。配方/两棵树/SID不一致、未知ACE、恶意并发或继承上级变化均可能使假设失效。

## 目录恢复与停止条件

恢复前核验预演状态、原始内容及对象集合、全部直接/潜在影响对象WRITE_DAC和审计链；每步写入前记录意图，完成后核验下一预演状态并持久记录。恢复不会删除新目录、写回旧内容、解除外部Deny或重建丢失对象。不能证明当前状态符合已演练步骤时必须停止。

恢复顺序从父目录到后代，以便父级传播结束后再核对和恢复后代的显式/继承状态；禁止分支不直接写入。测试比较允许普通Allow ACE的无语义换序，含Deny仍保留顺序约束，所有者独立检查。终态逐项核验原始内容和ACL，不以运行未抛错当成功。

恢复中再次失败，先记录停止与恢复位置，再在同一合成进程中显式验证续行；不是跨进程恢复工具或自动无限重试。遇到外部变化、审计不可写/损坏、权限丢失，保留现场，不冒险覆盖。

## 场景及证据

新增测试覆盖：实际父目录传播、未来文件、显式Allow/Deny保留、继承Deny与保护边界；三处逐对象中断及恢复；后代WRITE_DAC丢失；并发新增目录；禁止内容变化；审计文件占用、写入后不可用与损坏；恢复再次失败；恢复中外部变化；写入后出现未预期ACL；原生设置完成而完成记录未落盘时进程直接退出。

普通成功/停止场景保留directory-audit.jsonl与directory-result.json，包括原始快照、范围、观测快照、状态、故障与不能证明项。所有产物仅含合成信息，放项目外新测试目录，不进入Git。进程直接退出场景只保留prepared和write-intent等已落盘证据；没有completed或recovered，不能据意图推断成功，也不自动恢复。

未来新建文件在成功治理后专门创建，核对用户读写、禁止额外执行及普通用户组宽读取，另记录继承结果。这些新对象使旧清单失效，因此不尝试用原始清单恢复该成功场景。

## 真实治理仍缺条件

- 两个真实根目录由Administrators拥有，普通令牌WRITE_DAC问题未处理；不提权、不接管所有者。
- 未实现句柄绑定的对象身份与原子清单，仍有TOCTOU；创建时间和摘要不能代替Windows文件ID及全程句柄保护。
- 尚未验证任意真实树、多种父级继承、对象/回调ACE、SACL、跨账号有效访问、共享权限及管理员所有者场景。
- 审计哈希链并非签名；进程内尾部核对不是持久可信锚。审计与DACL不具原子提交，断电和跨进程可信续行未解决。
- 进程直接退出测试有意保留不确定写入窗口；不能称已实现崩溃后的可靠自动恢复。
- 某些传播可能部分失败；演练模型不匹配即停止，不宣称所有目录都能回滚。
- 新测试目录/拒绝夹具会改变原数据根清单，旧Plan继续失效。保留全部现场，不自动清理。

进入真实治理前，还需明确批准敏感白名单、禁止资产、继承边界及真实执行身份；审查可信审计和崩溃恢复设计，停写重新建立清单；独立授权真实权限操作。当前实验通过不构成该授权。

## 最终实测结果（2026-10-16）

新增14项目录测试全部通过；合并原92项共106项：105通过、0失败、1跳过。跳过仍为普通令牌无法创建符号链接（Win32 1314）；本轮没有为此提权。完整测试约205.8秒；四工作区typecheck/build通过，diff格式检查通过。
