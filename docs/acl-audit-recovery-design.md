# ACL 范围、审计及恢复：合成验证

本轮是2026-10-16的实验验证，不是生产执行方案。真实Windows账户继续采用普通令牌；不得自动提权。现有tools/windows-acl.ps1不变。未生成正式生产Plan，未执行真实Apply/Restore、数据库迁移或云端操作。

## 只读原型改动

windows-acl-scope.ps1现在完整遍历直接目标及禁止目录的后代，修复禁止分支位于直接树外时只记录目录本身的缺口。行记录增加明确的SID、Allow/Deny、权限位、显式/继承、OI/CI及传播标志，不把报告当可执行计划。

Get-SakieAclSnapshot重新遍历并记录绑定范围、对象类型、创建时间、所有者、DACL、文件大小/修改时间和SHA256。只保存内容摘要，不输出正文。Test-SakieAclSnapshot核验完整快照；哈希是准确字节状态检查，不声称所有语义等价ACL均给出同一哈希。旧执行脚本的Allow等价比较未变。

Get-SakieAclWriteDacPreflight刷新范围并逐一检查直接/可能受继承影响对象，不以管理员身份名称推断权限，不因为前面对象失败而跳过后面对象。禁止冲突或任何目标失败则Passed=false；受保护的禁止分支不是拟写对象，不请求其WRITE_DAC。所有探测句柄及时关闭，不写内容。

## 执行与恢复实验的限制

所有写入均在backend/test/fixtures/acl-recovery-lab.ps1当次创建的全新FixtureRoot内，启动拒绝既存根目录及已提升令牌。PutAcl核验目录边界、链接和对象存在性，仅调用原生DACL设置，不设置Owner/Group/SACL。该脚本是测试程序，不接受生产Plan，未向tools增加执行入口。

实验步骤：范围冲突检查、完整快照比对、全部WRITE_DAC预检、审计准备、逐对象写入前快照核对、落盘写入意图、DACL变更、禁止资产不变式核对、落盘完成记录。实验执行当前只针对两个合成文件；目录传播的实际行为由原有scope夹具覆盖，目录递归回滚未据此宣称实现。

审计使用递增序号、前记录哈希和完整载荷哈希的JSONL链，每次以FileStream.Flush(true)提交。记录准备、写入意图/完成、故障、恢复意图/完成以及需人工审查的检查点；报告成功前必须写完成记录。审计创建/写入失败时不继续新的DACL修改。哈希链可以发现局部篡改、乱序及残缺JSON，但不是签名，无法防御同用户重写整条链，也不能证明未丢失一个完整尾记录。

恢复在当前完整快照仍符合预期、范围安全且全部拟恢复对象WRITE_DAC通过时才进行；任何外部内容、ACL或清单变化均停止，保留现场，不能为恢复旧ACL覆盖新内容。恢复后核对原始快照。测试额外模拟恢复失败及部分恢复失败，显式从已校验审计链中的检查点恢复，而不是自动无限重试。审计损坏/截断拒绝消费；不自动修改或修补日志。

## 测试范围

新增用例覆盖：禁止目录树外的完整后代；相同大小/修改时间下内容变化；新增对象；显式Deny与继承Allow输出；直接和间接受影响对象全量预检；硬链接；符号链接（OS不允许创建则明确跳过）；执行前变化；成功审计；写入失败恢复；恢复失败/部分失败后检查点恢复；执行中内容/ACL/清单变化；禁止资产变化不覆盖；审计前后故障、文件独占占用；日志篡改和截断拒绝。

原有72项仍覆盖junction重解析点拒绝、Allow/Deny顺序语义、继承标志和未来文件权限、聊天/存储/同步回归。仅合成夹具，未用真实数据副本作为写入对象。

## 未解决风险与单独授权

- 文件路径检查到原生调用之间仍有TOCTOU；快照读取也不是原子快照。尚未全量持有文件身份句柄或抵抗恶意并发替换。创建时间不是可靠的Windows文件ID。
- 目录变更可能由Windows传播到后代；保守分析不是完整ACL模拟器，未实现目录整体可靠回滚、所有者/SACL恢复、管理员所有根目录恢复。
- 审计Flush(true)不能证明硬件断电安全。未测试进程在原生设置完成、完成记录写入前被杀死的实际崩溃窗口，也未实现跨进程自动恢复或日志可信尾锚点。
- 审计本身不可写、句柄占用、恢复权限消失时只承诺停止并报告，不承诺所有变化均回退。恢复状态需人工审核；不能称Windows ACL为事务。
- 符号链接创建是否可测取决于系统策略；不为此启用开发者模式、授予权限或提权。
- 实验产生新目录、故障证据、链接和故意拒绝夹具，均保留；根清单变化不能靠删除夹具匹配旧Plan。日志仅含合成数据，不应照此把真实审计放在宽权限目录。

真实根目录治理、任何真实ACL变更、服务停止/重启、生产Plan/Apply/Restore、可信审计存储及迁移到新SID均需另行明确授权。当前代码与测试通过不构成该授权。

补充：写入后的快照不能直接当作可信新基线。合成执行器现在逐项比对对象集合、身份元数据、内容及非本次目标的DACL，只允许本次指定文件的DACL变化。新增“原生写入完成、后置快照前出现外部内容变化”注入，必须停止且不覆盖外部内容。此检查仍不能消除原生调用之前的路径替换竞态。
## 最终验证结果

新增20项审计/恢复测试：19通过，1项因普通令牌创建符号链接返回Win32 1314而明确跳过，未提权。合并原有72项，总计92项：91通过、0失败、1跳过，耗时约57.8秒。实际junction和硬链接拒绝测试均通过，不能将符号链接跳过项描述为已实测通过。

四工作区typecheck、build及差异格式检查通过。完整回归前后，两份原拒绝夹具所在case目录的全量路径、SDDL（含所有者）及文件内容SHA256一致；既有windows-acl.ps1和旧真实Plan哈希一致。测试进程清空模型Key/模型配置并拦截外部fetch，只允许字面量127.0.0.1 HTTP。

最终新增用例包括原生写入后的并发变化不吸收为新基线；全部故障/恢复仅发生于全新合成夹具，没有触碰真实数据库或权限。未提交/推送Git。停止于本实验结果，真实治理与完善崩溃恢复须另行审查。
