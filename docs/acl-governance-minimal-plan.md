## 6. 普通运行账户最低访问设计

后端和local-agent均以艺11\hhdn普通令牌运行。SYSTEM与Administrators保留管理能力；管理员令牌只用于单独授权的维护，应用不能以管理员常驻。Owner保持原样；不为消除报错改Owner、SACL或组成员关系。

| 对象 | 当前运行用户最低操作需求 | 建议ACL配置方向 |
| --- | --- | --- |
| .env | 后端读配置 | Read、Synchronize；无额外执行/写入需求。后续编辑需单独维护，不借运行需求授予FullControl |
| auth\owner.json | 服务读取校验材料 | Read、Synchronize；创建/轮换需独立维护范围，不自动放宽整目录 |
| 数据库、WAL/SHM、工作日志 | 读写、创建/更新、需要的重命名/删除 | 数据目录Modify；数据文件Read/Write/Delete/Synchronize，不额外授予ExecuteFile、ChangePermissions、TakeOwnership |
| 备份目的地和维护产物 | 现有备份/演练工具创建、校验和写后续文件 | 对批准备份子树采用现有读写私有策略；不因计划中的只读归档而立即收窄到可能破坏SQLite旁文件操作的权限 |
| 验收副本/历史记录/凭据 | 读及已确认维护操作 | 默认采用数据文件私有策略，先去除其他用户访问；若需进一步改成只读，单独审查工具兼容性，不擅自改变历史资产使用方式 |
| 根目录本身 | 到达批准路径；现有工作流可能需列目录 | 首批不改变；未来只按实际需要设计，不能把普通运行维护混成FullControl |

目录需拆分当前用户的目录Modify继承与文件RWD继承，避免文件继承额外ExecuteFile；SYSTEM、Administrators的FullControl保留。只修改DACL，不新增不必要Deny。普通账户作为Owner可能具有Windows隐含的修改DACL能力；“不显式授予ChangePermissions”不能宣称防御同一账户恶意改ACL。边界是阻止其他普通用户读取，而非隔离账号本人或管理员。

现有private-rwd-v1脚本对全部文件要求RWD，不支持上述只读配置/身份文件的分类型验收；其成功日志在末尾写入且失败回滚策略不满足本次停止/留证要求。因此不能把该脚本原封不动用于整批真实治理。实验脚本也不能改个FixtureRoot就当生产执行器。

.env所在backend父目录仍宽。未来编辑器若以新临时文件替换.env，可能泄露临时内容或丢失私有ACL；最小阶段禁止普通流程用Save As/自动替换写秘密，编辑前先审查安全维护方法并在写入真实秘密前验证。不能用“编辑后再Verify”消除已发生的短暂泄露。长期私有配置目录方案可后续评估，不在本轮改配置路径。

逐项确定目标DACL；合法的显式授权不能因模板覆盖被默默移除。确认SYSTEM、Administrators与普通运行用户所需访问，不改Owner/SACL。继承传播与目标范围单独列出，受保护后代也不能漏审。

在授权的实际维护令牌下检查全部直接/潜在影响对象WRITE_DAC，并确认审计持久写入能力；任何失败零目标修改退出。重核清单、原始摘要和计划/脚本版本；批准目标ACL及步骤的哈希，不以刚读取的实际变更结果自动更新批准内容。正式Plan只能在该未来步骤另行授权后生成，本文无命令可直接执行。

### G4：小批次施工

S1先作为单文件批次，完成核验即停下给操作员检查。S2等目录先建立/核对私有边界，按已审阅顺序明确处理后代显式权限；不得使用E:\、data或backups为递归Target。每次原生变更前持久记录意图，之后核对预定的每对象DACL、继承传播及原始内容不变式，再写完成记录。

新观察快照只能当观测证据，不能直接成为可信下一步基线。合成预演的同构模型不能无条件推广到真实树；若真实树存在不能独立核验的传播，则进一步缩小到精确对象或停止该批次。

### G5：立即验收，不启动业务掩盖问题

- 所有批准对象的Owner、内容摘要与原始状态一致；DACL与批准目标逐项匹配，新增Deny/主体必须有明确批准；变更外对象无差异。
- .env/owner材料仅普通账户读；数据库/WAL/SHM/日志/备份符合各自profile；不把Private-rwd-v1的一次Passed当所有profile验收。
- 禁止case树及旧Plan内容/Owner/DACL/继承状态不变，无新链接、文件缺失或未批准对象变化。只允许普通Allow ACE等价换序的语义判定，禁止资产若要求字节不变仍需严格核对，不默默放宽。
- 同一普通令牌验证所需访问；真实数据库只检查权限/句柄能力，不打开数据库或写消息验证。新建文件继承可用批准子树内的新合成探针验证，须先获准、记入维护后新增清单，与原始冻结清单分开；不自动删除探针，也不借此创建真实凭据。
- 管理员退出维护令牌后再核对普通令牌。后台程序启动、模型调用、配对、迁移不属于本批权限验收。
- 审计完整且尾边界已外部保存后，才可报告“本批通过”；局部/未验证项明确列出。

### G6：维护后放行

仅在本批权限、内容和禁止资产核验通过后，提交用户审核；业务重启需符合授权，不能因ACL通过自动启动当前要求v4的后端去触碰真实v3库。数据库版本与同步启用属于独立任务。

## 9. 失败停止、未知状态与恢复决策

| 状态 | 处理 |
| --- | --- |
| 写入前哈希、清单、权限或审计失败 | 不改目标；记录失败/缺权限，不提权重试，不改计划迎合现状 |
| 意图已落盘但完成未记录 | 标记未知步骤，冻结后续操作；只读对比原始、批准目标和实际ACL，不能推断成功 |
| 外部文件/ACL/清单变化 | 保留新状态；停止，禁止覆盖内容、删除新对象或解除外部Deny；重新决定维护窗口 |
| WRITE_DAC执行中丢失 | 停止，保留具体路径/Win32错误及已完成步骤；不takeown、reset或自动追加权限 |
| 审计不可写/损坏 | 停止新ACL写入，保留原日志；如能安全另存故障观察则另存新证据，不修补原链或伪造完成 |
| 已知部分变更且可证明无外部变化 | 用户单独审核恢复范围与新开批次，在具备权限和完整原证据时受控恢复ACL；不恢复数据库/文件内容 |
| 不能证明恢复安全、恢复中再失败 | 继续停写留证，明确哪些对象仍变更；不自动循环重试，不为收尾覆盖当前状态 |

恢复旧宽ACL会重新开放普通用户组读取，应说明风险并单独批准；有时保留已成功私有化的对象、延后剩余批次比恢复原宽权限更安全，但必须逐项审阅，不能自动选择。恢复顺序需结合实际继承关系确定；父在前、子在后仅是已验收同构实验的结果，不是任意真实目录的通用回滚承诺。

绝不将旧数据库备份覆盖包含新消息的数据库，ACL故障不构成恢复历史数据的理由。

## 10. 必须保留的审计证据与交付

| 时点 | 证据 |
| --- | --- |
| 写入前 | 用户批准的范围/批次/profile/身份；时间、SID/令牌状态；工具版本与哈希；实际路径；停写确认；对象三类清单；Owner/原DACL/继承；内容摘要与元数据；备份既有证据；目标ACL及步骤；全部预检结果；禁止资产基线；私有审计目的地ACL |
| 每步 | 序号、操作者/令牌、对象、写入意图、批准前态/目标态引用、原生错误、观察后态、传播差异、内容/禁止不变式、完成或未知状态、日志尾边界 |
| 停止/失败 | 首次故障、最后确定完成步骤、未知步骤、原生错误路径、未修改与仍变更清单、审计健康度、外部变化及恢复被拒原因；另存证据不得覆盖原日志 |
| 恢复 | 独立批准、恢复范围/顺序/权限、每步前态条件、结果；原始快照核对，未恢复对象及原因 |
| 验收后 | 每个profile结果、普通令牌能力、禁止资产严格一致性、内容/Owner不变、探针新增清单、人工留存哈希、未验证项、根/待分类风险、是否获准重启 |

证据只记录秘密文件路径/权限/摘要，不写密钥、会话Token、配对码或聊天正文。文件摘要和路径仍按敏感审计材料保管。可进入源码Git的交付仅为去敏说明，不包含真实清单附件。
