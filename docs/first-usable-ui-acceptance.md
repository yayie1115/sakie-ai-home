# 小家第一版可用界面：并行 UI 验收卡

依据：`docs/sakie-ai-home-产品需求与交互规范-v1.1.md`。此卡是后续 UI 开发和验收的明确边界，不表示已实现或获得生产部署授权。Codex 当前主任务仍为第二阶段 Windows ↔ 首尔真实同步；本文件可供其完成该任务后直接使用，不与正在修改的源码竞争。

## 目标

把已经跑通的 `/demo/chat` 白板功能演示，升级为用户实际愿意打开的第一版小家。**不等于开发全部页面功能，更不能提前声称长期记忆、自主活动已完成。** 优先让真实聊天核心流程呈现在产品外壳中。

## 视觉与信息架构（必须遵守 v1.1）

- 网页同时兼容 iPhone 与 PC；清透极简、雾白/深灰蓝主题、雾霾蓝强调、线性图标、轻量消息气泡；无额外网站大标题。
- 主导航严格为 **Home / Chat / World**（中文 UI 文案可按规范），侧边栏为推开式。不能以旧演示页的顶部八个文字链接冒充正式导航。
- Chat 顶栏：左侧栏入口、中间 AI 备注名 + 小号实际模型名、右侧详情；**顶栏不放头像**。消息气泡展示双方头像，滚动时收到新消息不能强制拉到底。
- Home 框架：纪念卡（两人头像/爱心/天数），横向音乐卡，四格依次为**他的状态、日记、今天、情绪**；未开发的入口可标「暂未启用」，不得伪造 AI 实时状态或假日记。
- World 可先展示模块入口占位；未启用模块点击后说明状态，不要渲染不存在的动态或游戏内容。

## 首批可点验收

1. 手机上能完整看到底部主导航、聊天区域和输入框；桌面不出现拉伸失控或横向溢出。
2. Chat 能按当前已实现的真实接口登录、发消息、接回复、刷新保留历史；测试环境明确标识假模型，不把假回复当成真实模型。
3. 输入和发送失败有清楚状态，发送按钮不会重复触发已提交消息；不把同步未验收的功能表述为「已经云端可靠备份」。
4. 未接通的图片、语音、日记、情绪、梦境、长期记忆、自主操作等只做明确占位或暂不展示；不能用假按钮误导。
5. **待提交多条气泡、版本切换、引用、AI 真实操作小字、按需历史加载**是正式 Chat 的已确认需求；可以后续迭代，但第一版不得用单个普通发送框暗示这些需求被取消。
6. 切换主导航再返回聊天，已持久化消息仍在；UI 草稿/滚动位置的复杂恢复若暂未实现须在报告列出，不虚报通过。
7. 只在隔离数据、假模型环境做首轮界面验收；真实 API Key、Windows 主数据库、VPS、DNS、Nginx 不因本卡而获得操作授权。

## 交付形式

下一轮独立 UI 工作应交付：实际运行页面的移动与桌面截图或可访问的本机演示、可复现的启动命令、简洁通过/未实现清单。尽量集中实施与批量验收；不要再次提交只有设计概念而无界面的审查长文。

## 与当前关键路径关系

- 第二阶段真实同步、权限与正式部署仍为当前主线；本卡**不要求中断 Codex 当前工作**。
- 旧上海 VPS 2026-10-22 到期前，根域名与 www 的解析仍需独立处理。不能为了抢进度把未部署的 UI 挂到正式域名。
- Phosphene 已独立部署在 phos 子域，不能覆盖其 Nginx 配置或复用其数据。
