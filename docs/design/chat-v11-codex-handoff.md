# Chat 正式前端实施交接 · 2026-10-18

## 权威输入与状态
- 已提交可交互原型：`docs/design/chat-v11-interactive.html`。用户表示“基本都是对的”，以此作为**当前视觉和交互基准**，并非生产代码。
- 既有产品规范：`docs/sakie-ai-home-产品需求与交互规范-v1.1.md`（若路径变化先在仓库确认）；现有前端代码和测试是工程现状。
- 本文合并用户在 v11 确认前的**较新 Chat 决定**；与旧版“单一 Chat 入口直接聊天”的规定冲突时，以此为准。
- HTML 原型中的演示消息、成员、模型、Tokens、缓存均为合成占位，不能当作真实数据。

## 信息架构（必须）
1. 点击全局 Chat 先进入**会话列表**，而不是直接进谢亦言私聊。手机为列表→聊天内容两级；PC 左侧常驻列表、右侧聊天；不弹多个网页窗口。
2. 会话列表支持**搜索、置顶**；明确**不提供免打扰、归档、仅隐藏会话**。会话按最近真实活动时间排序，置顶项在前。手机长按/PC 右键可置顶或删除会话，列表行右侧只显示时间，**不显示行尾三点**。
3. **新建私聊**先选择 AI：该角色已有长期私聊则进入既有历史，无则创建相应会话；**新建群聊**必须先由用户选成员（初始无人勾选）再确认创建，禁止自动预加两个 AI。
4. 私聊顶栏：角色备注名**严格居中**，其下预留真实当前模型名；顶栏不放头像；右侧三点进详情。群聊顶栏：严格居中的**可编辑群名称且仅一行**，不显示成员数和模型副标题，右三点进详情。
5. 私聊角色备注、各群聊名称、各群的成员备注是**独立字段**。私聊/群聊备注编辑框必须读取各自对象当前值，不串值；改群内某成员名字不改变私聊或其他群。
6. 同一个 AI 在所有私聊和群聊使用**共用模型配置、连续人格**；但记忆及历史访问受会话权限隔离。群内发言行为按群单独配置。新 AI 加入群聊后可见**该群完整历史**，但不因此获得其他会话权限。

## 消息、头像及操作
1. 双方头像是圆形，直径与单行消息气泡的高度基本一致；每条气泡旁都显示头像。**私聊 AI 气泡上方不出现姓名**。群聊 AI 名字在气泡上方，**名字与头像顶端大致齐平，名字和气泡间距极小**；遵守原型最近确认的布局。
2. 用户默认淡雾蓝气泡、AI 浅灰白气泡。同一回合允许多独立气泡，组内间距较小。
3. 普通**单击消息不得高亮选中边缘**。长按气泡（PC 可右键）才进入消息操作态，目标气泡与头像保亮、其他弱化；操作工具条**始终紧邻气泡下缘**，绝不为了避免碰底改到气泡上面：下方空间不足就滚动聊天内容向上腾位置。关闭后尽量恢复阅读位置。
4. 工具条支持复制、编辑、删除、引用（可选部分文字）、AI 单泡重生成/整轮重生成和版本切换；菜单避让气泡正文并支持点空白收起。成功重生成的当前版本才进入模型上下文/搜索/记忆。
5. **引用**参照微信式：独立引用预览栏，不把引用原文插进输入框正文，可取消。各会话的**草稿、引用、待提交**独立保存，切换私聊/群聊不串值；暂存及最终提交后输入框不得残留已经提交的内容。手机输入字号避免 Safari 自动缩放。
6. 待提交气泡直接显示在聊天时间线底部，有清晰待提交标记，可编辑、删、重排。输入暂存不调用 AI、不中断当前生成；最终提交才触发 AI。
7. 用户回合末尾时间；AI 回合末尾展示**真实可得**的 Tokens、缓存占比和时间，缺少数据不能造数字。长聊天历史按需加载，读旧消息时有新消息不抢滚动，可跳第一条未读。
8. 多图同次选择为一张横向滑动卡片；图片全屏缩放/切换/显隐工具栏；语音独立气泡、单条播放/拖进度/折叠转写，无倍速。AI 真实跨模块操作以持久小字事件显示，成功与失败区分。

## 详情、历史搜索、回收站
- 私聊详情保留修改私聊备注、真实模型信息、**历史聊天搜索**、**图片与文件**、**默认音色**等独立项；去掉关于“我”的重复内容，**不放删除会话按钮**。
- 群聊详情支持修改群名称、群成员列表/成员独立备注及配置、群内行为设置、**搜索本群历史聊天**。
- 历史搜索采用**独立完整页面**而非小弹框：关键词、日期筛选、结果列表滚动/按需加载、命中高亮、点击跳原消息并可返回保持搜索状态；只搜索当前生效版本。
- 删除整个会话仅从**会话列表长按菜单**触发，二次确认；包括谢亦言长期私聊也可删除。**不提供清空会话但保留会话**功能。
- 删除会话进入**30 天统一回收站**，期间可恢复，到期永久删除；统一回收站为独立页面，顶部标题下横向类别标签，Chat 可深链到“会话”分类的相应条目。暂存回收站时不得继续使用仅由该会话支持的记忆；永久删除时清除独属于该会话的记忆与派生检索资料，多源记忆保留其他独立证据支撑部分。不能无条件删除媒体库其他模块原件。

## 外观与验收
- 设计语言：清透极简、默认雾白/深灰蓝、雾霾蓝强调色；后期支持**主题、全局强调色、双方气泡色、聊天背景/壁纸**可调。正式实现使用集中的 CSS 主题变量/配置，不写死在组件里。
- 不得把 HTML 原型直接塞进 React 生产页面；先检查现有路由、Chat 模块、后端协议，提取可维护组件。
- 先用合成数据在隔离前端构建可运行交互；做端到端测试覆盖：私聊 A 草稿→群聊 B 草稿→返回 A、引用独立、发送清空、创建新私聊选择、新群未选择成员时不可偷建、长按气泡操作栏始终在下方、底部滚动让位、历史搜索结果跳转、跨群备注隔离、置顶/时间排序、会话回收站恢复。
- 不得修改真实主数据库、生产服务、密钥、备份、ACL，不得触发真实付费模型。不要将本次交接视为数据库迁移或生产部署授权。
- **先提交差异盘点、分步实现计划与风险**供用户核对，再实施前端。现有 v11 HTML 是验收基线，但仍须依据旧正式规范查漏；不要反复问已确认事项。
