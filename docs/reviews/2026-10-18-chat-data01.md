# CHAT-DATA-01：规范化气泡、版本与隔离联调验收

日期：2026-10-18。基线：`2376302`。本次只交付合成候选，不是生产迁移或生产验收。

## 实际交付

- 在同一个 SQLite 复用 `chat_conversations`、`chat_turns`、云端 turn 顺序、单一未完成 turn 约束和 `ChatStore.transaction()`。没有第二个聊天数据库，也没有将多气泡 JSON 写进 `chat_messages.content`。
- 追加规范化的 `chat_bubbles`、`chat_bubble_versions`、`chat_bubble_states`、`chat_bubble_quotes`；一回合可有多条独立用户/助手气泡，UUID 稳定，按 turnSeq → role → position 排序。
- `chat_bubble_operations` 保存规范化请求哈希及持久回执。相同请求重放返回原回执，改变内容、顺序或复用气泡 ID 会拒绝。批次、版本、回执和事件共同提交，写入中断全部回滚。
- 单泡编辑保留历史；切换版本只更新指针并递增来源 revision，切回旧文本不会使旧证据重新有效。不会编辑或重生成后续回复。
- `chat_bubble_jobs` 保存首次回复/单泡或整回合重生成的输入来源快照、目标版本、状态及结果哈希。整回合重生成只能更新既定助手气泡集合，原子激活；目前不支持改变该集合的数量。
- running 中断转 unknown，不自动重发；人工显式确认后才可重试。明确失败可显式重试同一任务；迟到、冲突或过期输入的输出被拒绝，不记成成功。
- `chat_tool_events` 独立持久记录工具事件，与普通文本气泡分离。本轮不执行真实工具，也不承诺外部副作用恰好一次。
- `sources/search/evidenceCurrent` 仅返回成功 turn 的未删除当前版本；每次重新检查调用方的授权，失效、撤销、来源变更或受众变化不能成为新的有效证据。源版本为 `revision:activeVersionId`。

## v4 兼容边界与同步安全

1. 正式 v1—v4 SQL、校验和、正式 `latestVersion=4`、消息奇偶序号、UUID、原消息哈希、原 outbox 和 Agent 均未修改。
2. 合成迁移导入已有原始消息及 v4 当前状态，保留其消息 ID。若旧库只保存原始第 1 版和最新第 4 版，只建立这两版，不虚构缺失中间历史。
3. `data01Migrations` 的第 5 步只供显式标记的新合成 SQLite。**不是正式 v5 分配，不可与 memory-next 的未来迁移各自直接上线**；正式整合时须统一迁移号、写入器与协议能力。
4. 新气泡写入 `chat_bubble_outbox`（稳定事件 ID、连续本地序号、SHA-256、同事务持久化），不将旧 Agent 不认识的事件塞入 v4 流。`archived` 被约束为 0，`archiveReadiness()` 始终 `canPrune=false`。**尚未实现新事件的双端投递、ACK 或归档**，旧 ACK 绝不代表新气泡已归档。
5. 候选库禁止继续写入旧 `chat_messages` 和 `chat_message_state`：旧入库器会在自身事务内失败回滚，避免混用导致奇偶序号空洞或新旧状态分叉。正式 v4 库无此触发器。合成升级还会在迁移事务内拒绝存在未完成旧 turn 的 v4 副本，避免把旧任务变成无法恢复的候选任务。**不可将候选库交给正式旧 worker 运行。**
6. 服务和迁移入口只接受内存夹具，或带专用文件名、目录名及合成 marker 的文件；检查重解析链接、真实路径和硬链接数。运行器在打开数据库前执行路径检查。

## 剩余差距与下一批顺序

1. **同步/API 阻塞**：先确定正式迁移顺序、兼容读写模式、归档事件能力协商及新 Agent 消费/持久 ACK，再考虑正式启用；本轮未修改正式同步协议，候选不能直接生产部署。
2. **API/UI**：编辑、版本选择、删除和重生成已在服务层验收，尚无 HTTP/UI 操作闭环；现有 linked Timeline 仍禁用这些持久操作。下一批接隔离 mutation API 与已有菜单，不另建 UI。
3. **权限**：目前只有 owner 合成私聊。群成员、说话人、角色级授权、跨私聊引用及群受众变化的正式策略/持久化尚未实现，默认拒绝跨会话引用；不能据此宣称群聊权限已验收。
4. **记忆**：只提供当前来源投影及实时核验接口，没有改 MEM-04、现有提取/审核实现，也没有将新源注册到正式记忆索引或主动传播失效事件。正式消费方必须调用 live evidence check，不能持久缓存授权结果。
5. **资源**：没有生产负载测量。当前历史读取与来源快照未分页，版本/事件会累积；正式启用前需有界查询、索引与预算验证，不能把合成少量数据表现当作 2 核 4GB 的容量结论。
6. **恢复**：测试恢复仅指合成进程/任务重启与事务回滚；不提供真实库降级/覆盖恢复，未读取或触碰真实主库、备份、凭据、ACL、云端、DNS 或付费模型。
