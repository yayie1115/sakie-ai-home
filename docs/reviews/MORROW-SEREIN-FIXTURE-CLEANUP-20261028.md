# 测试资料污染与会话标题误判修复

## 实际原因

此前 Codex 在正式服务中创建的验收 Scene 留在正常记忆池，删除聊天会话并不等于删除独立 Scene。只在正文写“虚构验收”并交给模型自行判断，不能构成可靠隔离。

另一个实际缺陷在 `auto_text_memory.source()`：仅根据会话标题前缀判断 synthetic，并把这个判断加入来源哈希和 Scene 正文。用户后来继续在 Codex 创建的会话输入新信息时，也被错误添加了虚构标签。因此不能把整个带测试标题的会话一概删除，更不能按水果等内容词判断归属。

## 已部署修复

运行代码：`a38ce7e3c19bea1eafcdc68dcb98683ef3021b14`。文档后续提交不需要再次部署。

- `auto_text_memory.py` 不再读取会话标题，不再根据标题添加虚构标签；来源身份由消息、版本及正文决定。保留旧非测试任务的哈希格式，避免破坏已有普通任务和幂等回执。
- `tests/test_auto_text_memory.py` 验证：测试样式标题不会把用户原话判成虚构；修改标题不改变来源、任务 ID、模型输入，也不会重复排队。
- README 明确测试应使用独立数据库，标题前缀不是隔离边界。正常记忆仍保留原话摘录、表达时间和“当时自述”的限定；不无条件把所有记忆当作事实。

源码检查：正常 `chat_engine.get_history()` 构造的是消息及有效版本，并未把会话标题注入为用户事实；本次确认的错误来自自动提取前的宿主标题判断。历史检索工具中的标题用于定位，不是个人事实证据。

## 精确清理结果

根据此前私有执行记录、稳定 Scene ID、任务回执、消息 ID 与创建时间交叉核对，未按内容关键词批量删除。

| 对象 | 实际处理 |
| --- | --- |
| 4 条确认属于 Codex 的测试 Scene | 通过运行服务实际提供的 `set_scene_status` 与更新时间 CAS 置为 deleted；不是直接删数据库行 |
| 测试 Scene 检索索引 | 原生后台索引处理后，主索引中 4 个精确 ID 的剩余记录为 0 |
| 测试 Scene 读取 | 逐一调用读取接口，均不再返回正文；正常召回也未返回这些 ID |
| 2 条确认是 Codex 创建的测试消息 | 通过现有消息删除 API 移除 |
| 后来被用户继续使用的同一会话 | 保留用户后续消息和 AI 回复，只移除 Codex 的两条测试消息；Codex 原设的测试标题改为中性标题，未新建替代会话 |
| 1 条因标题而被误标的用户记忆 | 核对消息版本、来源哈希、摘录与 Scene 回执后，只删除宿主误加的标签；保留正文、日期和修订历史 |
| 另一条用户记忆 | 完整文档前后核对一致，未修改 |
| 旧测试任务 | 精确关联的旧自动任务标记 retired_fixture，避免作为正常去重成功记录继续使用；保留写入回执供审计 |

清理前有 6 个 canonical 文档：4 个已确认测试对象，2 个用户来源对象。未发现额外带明确标记但无法归属的候选。已被用户提前删除的测试会话未重建。剩余非目标消息逐条核对正文不变。

deleted 是 Serein 原生保留式删除：不再能正常读取或召回，修订审计与私有备份仍保留，并非承诺物理抹除磁盘全部副本。没有删除用户原话、人格或旧记忆，也没有回灌旧数据库。
