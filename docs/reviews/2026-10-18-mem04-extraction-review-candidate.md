## 实际实现

新增 `backend/src/modules/memory-next/extraction-provider.ts`：供应商无关的 `ExtractionProvider`；模型版本、批次、指令及 AbortSignal 通过依赖注入传递。输出仅允许严格 JSON，无 Markdown、额外字段或重复 JSON 键（包含转义后的同名键）。校验根版本、五类 kind、字符串、有限数值范围、主观标记及输出/候选/嵌套上限。未引入依赖、模型 SDK 或真实供应商适配器。

新增 `backend/src/modules/memory-next/extraction-service.ts`：`IsolatedMemoryExtractor` 组合既有 `buildMemoryExtractionBatches`、`ParticipantGrantResolver` 和 `MemoryPipeline`，保留现有生产表、服务、接口及文件不变。

流程：当前授权与权威范围核验 → 当前来源投影 → 复用既有批次 → 顺序调用注入模型 → 严格 JSON 校验 → 本批来源与逐字证据核验 → 全批次成功后发布待审核候选 → 独立审核器批准 → 既有记忆管线验证与内存提交。未配置审核器时只能待审核；模型置信度不等于批准。后批失败不会发布前批候选。源消息作为不可信数据封装，不能用聊天中的指令设置审批、所有者、权限或 ID。

事实 fact、偏好 preference、经历 event、承诺 promise 当前采用保守规则：`basis=explicit` 且 statement 与 evidenceQuote 完全相同，不接受模型意译或推断。主观印象 impression 必须 `basis=interpretation`、`perspective=self`，与事实区别保存。引用只证明说过这些话，不能证明客观真实性；语义真实性及类别是否合理仍依赖独立审核策略。未实现世界事实验证器。

候选保留来源消息 ID、版本、事件 ID、完整来源指纹、证据原文、UTF-16 起止偏移、置信度、重要度、提取模型/策略版本、授权版本、会话、所有者及 private/group 范围。候选 ID 由服务端内容指纹确定，不受模型指定。相同内容在不同任务中复现不会覆盖已批准记录；同任务并发复用一次调用，任务输入变更则拒绝复用；失败任务允许显式重试，无自动轮询或重试。

授权在模型调用前后、审核前后及召回/检查时重读。来源内容、版本、事件或权限发生变化，异步任务安全失败。编辑、删除、撤权及重新授权会使旧候选失效，并在下一次访问时从本实例记录中移除；旧任务缓存仅存 ID 与指纹，不保留候选正文。已返回调用者的对象无法追溯擦除；没有后台删除传播服务。

召回与检查以 actorId + conversationId + audience 隔离。可信 `CurrentEvidenceReader` 必须返回真实会话和范围；混合私聊/群聊投影拒绝处理，其他会话及其他群的候选不可读取或审批。不能拿调用者提供的群聊标签包装旧私聊读取器。既有 `chat-v4-reader.ts` 只有私聊投影，本轮不冒充已支持正式群聊。

记忆修订继续使用既有 supersedes，增加保守约束：只允许同一当前来源版本、同一 kind、同一权限范围的已批准前项，拒绝重复分叉及冲突批准。跨来源/跨版本语义合并尚未实现；来源编辑后整条旧链失效，不将旧证据重绑到新版本。这样不会构造既有 snapshot 无法重放的跨来源依赖。

## 使用边界与配置

服务只导出隔离类，没有被 app/server/生产路由引用。通过构造参数注入当前授权解析器、可信当前来源读取器、模型及独立审核器；`extract(context, jobId)` 返回待审核证据，`reviewAndCommit(context, proposalId, supersedes?)` 才可能批准，`recall(context, query, limit)` 在明确的会话范围内检索。`inspect` 仅用于合成验收，不可直接作为生产端点。

可配置默认上限：单批 12,000 字符、单次输出 64,000 字符、每批 32 候选、每次 100 来源/8 批、30 秒超时、2 个并行提取任务、64 个任务记录和 2,048 候选记录。均为工程保护参数，不是召回策略或资源实测结论。已有分批函数保留单条超长消息，本候选会在模型调用前拒绝超长批，不偷偷截断证据。达到容量时失败停止，不驱逐幂等记录。需要调用方在受控生命周期结束后释放实例；未实现长期任务仓库及淘汰机制。

`provider.version` 应由可信适配器固定，模型/提示策略变更时更新。适配器需要遵守 AbortSignal：本候选能拒绝超时或迟到结果，但无法强制停止无视取消的第三方客户端，也不能据此保证没有供应商费用。没有真实模型调用、Token/费用结算、独立审核模型或生产调度。

## 正式集成前门槛

适合进入下一轮正式数据库集成**设计与合成事务验证**，不适合直接接入正式库或宣告自动记忆可用。尚缺：

1. 权威的会话参与者/私聊/群聊映射与当前版本投影适配器；旧生产读取器只支持私聊，不能依赖调用者标签授权。
2. 在同一 SQLite 连接与事务中核对当前来源版本/内容和授权版本，并持久化候选、审核结果、证据、修订和幂等任务状态。既有 `source-atomic.ts`/`grant-guard.ts` 可复用，但单来源原子门槛不等于本轮多批服务已具备正式事务安全性。
3. 审核器准入、语义证据标准、授权生命周期及来源编辑/删除的持久化传播策略。这里仅做当前访问时失效，不承诺跨进程、离线副本或既有调用者缓存已删除。
4. 重启后的持久幂等、任务生命周期/容量回收和多进程竞争控制；本轮仅单实例内存去重。
5. 真模型结构化输出兼容、提示注入与语义误判评估、脱敏日志及实际 Token/预算接入、目标机器资源测量；本轮均未验证。
6. 任何正式表变更应另行评审并在备份副本验证迁移/回滚。本轮没有改表要求或架构覆盖，也没有实施迁移。
