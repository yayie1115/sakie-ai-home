# Morrow + Serein 官方分叉接管报告

日期：2026-10-28（UTC+8）。本轮按用户新指令执行：以两个上游源码及其行为为准，不继续扩展旧版自定义记忆认证架构。

## 1. 实际交付与版本

Morrow 的源码变化：`serein_connection.py`、`chat_engine.py`、`tests/test_serein_connection.py`、安全配置模板及说明。连接层只改变普通聊天的模型传输路径，不实现另一套记忆提取、排序、人格或认证规则。

Serein 的源码变化：`deploy/Gateway.Dockerfile` 增加现有前端 base-path 构建变量；`deploy/compose.constrained.yaml` 提供资源和日志限制；`docs/fork-connection.md` 说明连接边界。没有重写上游 UI、提示词或记忆规则。

## 2. 已部署并启用

- Morrow 原版网页与原有登录；保留聊天、人格、提供方配置、日记、笔记等原数据。
- 普通聊天通过官方 Serein OpenAI-compatible Gateway 调用原先选用的聊天模型。提供方原始记录不被替换；稳定窗口 ID 将同一 Morrow 会话关联到同一 Serein 窗口。
- 使用官方 Gateway 的记忆召回和上下文注入；复用已选的向量、重排及 Event 模型连接，没有重新选择聊天模型。
- 使用官方 Gateway 的新回合原话归档，用户与 AI 内容作为原话保存，不将其伪装成用户事实或 Scene。
- Morrow 配置官方 Serein MCP，实际发现 23 个工具；Scene 读写、修订等按上游工具语义提供。工具是否被模型调用仍取决于模型与实际对话，不能宣称每句偏好都会立即生成 Scene。
- Serein 原版管理页面部署于主站 `/ob2/`；其官方浏览器 API 独立转发，不覆盖 Morrow 的 `/api`。
- 官方 Event 后台调度已开启，按上游日界线在 UTC+8 的 03:00 结算；不是每条消息立即生成 Event。近期数据也可从原版管理入口手动处理。
- 独立 Docker 服务、仅回环地址发布 Gateway、受保护的管理入口、日志轮转、内存/CPU 限制和开机启动。
- 复用现有认证加密备份工具，为新的数据与私有配置提供备份；完成一次实际备份及独立解密恢复校验。

管理入口使用独立 HTTP Basic 登录保护。访问凭据只保存在私有部署材料中，不包含在本报告、Git 或前端代码中。Python 数据库服务没有发布宿主公网端口。

## 3. 数据保护与正式切换

1. 旧站仍运行时，制作 SQLite 一致性备份并恢复到独立文件验证完整性；先执行现有加密备份。
2. 主站临时维护，阻止新公网请求；等待已有聊天连接与聊天、记忆、标题等任务排空。
3. 停止旧专属服务，制作停写后的最终一致性备份，并再次独立恢复。
4. 从冻结的原数据建立全新运行实例，原目录、数据库、配置及历史备份均保留。
5. 仅在新副本移除旧包装层专属的 73 个自定义触发器；未修改上游规则或旧数据库，未伪造旧认证状态。旧控制表作为历史保留，不作为新系统的认证依据。
6. 对聊天、人格、提供方、旧记忆、日记等受保护表逐表比较哈希；Serein 原有 documents/revisions 也比较一致。新实例的官方索引实际准备成功。
7. 更新主站独立路由，启动新服务；检查登录、历史接口、跨源拒绝、静态资源、Gateway 模型目录及 MCP。
8. 新实例加密备份恢复校验成功后，才移除维护状态。未向正式聊天或正式记忆插入验收材料。

旧自定义包装服务与模型代理同步定时器已停止并禁用；旧源码、数据及未完成开发没有删除。现有其他网站、证书、DNS 和独立服务未改动。

回退边界：切换脚本在开放新写入前失败会恢复旧程序和路由，不还原数据库快照。现已开放新写入，后续如需回退，必须先停写并核对新数据，不能直接切回旧数据路径或用旧快照覆盖新聊天。

### 独立服务进程与真实模型联调

使用独立数据库、独立端口和完全虚构消息，没有把测试水果、偏好或会话写入正式库：

- 官方 MCP 写 Scene → 生成索引 → Morrow 经 Gateway 召回 → 实际模型回答：通过。
- 两个不同窗口分别保存用户和 AI 原话，共验证 4 条新增原话；窗口身份独立且稳定。
- 真实 Event 管线经过 router、curator、writer，得到 1 个有效 Event 和 2 个原话证据绑定；相关批次完成，失败数为零。
- 重启独立 Morrow 与 Serein 服务后，聊天、原话、Event 和证据仍可读取。
- 观察到一次含召回的模型请求总耗时约 72.7 秒，另一请求约 21.7 秒。这是完整请求时间，不是适配器额外延迟；不能据此承诺模型回复速度。

联调初期发现 Windows 与 Linux 资源换行字节不同造成原生索引资源哈希不匹配。已从 Linux 固定版本源码重建最终镜像，确认资源一致后，仅在测试实例使用官方恢复入口恢复索引。正式实例原生准备通过；没有绕过哈希检查或直接修改认证状态。

## 5. 明确未做与行为变化

- 没有移植旧版强制自动提取或“请记住”的宿主兜底逻辑。Scene 的主动写入遵循官方 MCP/模型行为，原话归档和后台 Event 不等于逐句即时 Scene。
- 没有实现“删除 Morrow 聊天就自动撤回 Serein 独立记忆”的旧产品要求。上游两套数据独立；删除聊天不能当作外部记忆已删除，需在 Serein 中管理。编辑、版本切换也不宣称具备旧自定义同步协议的级联撤回能力。
- 没有把旧 source guard、Receiver、认证常量、七库恢复等机制重新打开；旧未完成修改已保留但未部署。
- 没有保证 Serein 故障时 Gateway 路由可自动切回原模型；本轮保持官方行为和私有路由配置，不复刻旧故障降级框架。
- 原版可选功能页面与接口保留，但缺少配置的语音、图像、主动行为等能力没有伪造为已启用，也没有替用户开启所有收费后台模型任务。
- 没有导入 Aru 历史、批量补录旧聊天、改变人格或编写新的人设。
- 没有对新上游做完整安全审计，也没有把服务器接口通过写成 iPhone Safari 用户验收通过。

## 6. 用户操作与后续维护

在原主站使用现有密码登录 Morrow；访问同一主站的 `/ob2/` 可进入 Serein 原版管理页。可以查看原话、Scene、Event 及模型/管线状态。管理页登录说明通过私有交付告知，不在公共源码记录口令。

建议用户先正常聊天，再在原话页面确认本轮新增记录；需要立即观察 Event 时使用官方近期处理入口，否则等待原生结算时间。Scene 写入需模型实际调用工具，不能仅凭回复“记住了”就认定持久化成功。

之后维护以这两个 fork 的固定版本为准；升级应先独立验证并备份。不要把旧仓库中的未提交自定义记忆修改直接覆盖到新部署。
