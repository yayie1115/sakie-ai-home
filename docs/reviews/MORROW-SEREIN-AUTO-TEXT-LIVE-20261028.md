# Morrow + Serein：普通聊天自动记忆修复（2026-10-28）

## 原因与本轮修改

原来的宿主保存路径只识别明确的“请记住”等请求；聊天模型如果没有返回工具调用，普通偏好声明不会成为 Serein Scene。模型口头回答“记住了”不代表存储成功。

此外，实际 Hook 调试确认“我最喜欢的花是什么？”可被 Serein 的 `present_chitchat / published_skip_route` 在检索前跳过。这与写入失败是两个不同问题。

- `auto_text_memory.py`：真实发送接口提交用户消息后，仅将本条新文本排入现有 Bridge 私有账本的 `auto_text_jobs`。后台使用该次聊天选中的供应商和模型，进行独立、非工具调用式的语义提取；不扫描旧聊天，不建立新的记忆检索数据库。
- `app.py`：正式发送接线、进程启动时恢复待处理任务，以及受现有登录保护的 `/api/serein-memory/auto-status`。状态接口只返回任务状态、错误码、Scene 回执和耗时，不返回消息或候选正文。
- `chat_engine.py`：继续使用现有 Hook；禁止把尚无成功回执的后台保存说成已经完成。进入新会话时，若别的会话有近期待保存任务，最多等待 8 秒；普通后续回合不等待提取。
- `serein_bridge.py`：保留原显式保存路径。Hook 空结果且明确跳过个人记忆问题时，调用 Serein 已有的 `recall_memory(mode=lookup, method=semantic)`，最多两条、2 秒超时；不修改上游路由、阈值、可见性或来源保护。
- 配置模板和 README：新增默认关闭的自动提取配置及行为说明。生产只改变本项自动提取设置，不改变聊天供应商、密钥或人格。

## 保存与失败语义

模型返回必须为严格 JSON；类型限长期偏好、稳定个人信息和重要约定；证据摘录必须是当前用户文本的连续原文。普通闲聊、问题、推测和临时状态由语义提取判断为不保存。精简解释不能当作已认证原始档案。

稳定任务 ID 关联会话、消息和当前内容哈希；提交前再次核对来源。重复队列和完全相同的表达去重；发生偏好变化时追加带时间的新 Scene，保留旧记录，不直接覆盖。提取最多重试一次；写入丢失回执标记 unknown，复用现有 Bridge 未知写入阻断，不能盲目重复。没有 Scene ID 不标记保存成功。

这是新文本的独立 Scene 通道，不代表原话同步、完整来源撤回或自动 Event 通过。既有保护模式不允许时不采集。既有 raw sync、Receiver、来源 worker 和 Event 开关不因此开启。

## 数据保护与范围

部署前分别进行 Morrow 主库和 Bridge 账本一致性备份，实际恢复到独立文件并执行 integrity_check；复用既有 Serein 加密备份任务。核心 Morrow SCHEMA 未改变，仅在既有 Bridge 账本新增任务表和索引。旧消息、会话、记忆和供应商记录保留；环境文件与供应商、旧记忆内容哈希核对不变。

保留旧程序和私有配置回退材料。若需停用本功能，可关闭自动提取配置并受控重启 Morrow；程序回退不回灌旧数据库，不覆盖新消息或新 Scene。具体私有备份地址与运行证据仅存服务器受限目录，不上传。

测试会话及 Scene 明确标记为虚构验收资料，不代表用户现实偏好，未清理或覆盖用户数据。没有进行历史补录、Aru 导入、Event 自动整理或其他服务部署。

## 已知边界

- 异步保存存在可见性窗口；超时或服务故障可延迟/失败，不能保证所有自然表达都能被模型正确分类。状态接口可追踪，普通聊天保持可用。
- Scene 的保存回执和语义索引就绪是两个阶段；立即跨会话询问仍可能暂时漏掉最新记忆或只读到较早记录。这是本轮实际观察到的剩余问题，不是已经通过的项目。
- 同义重复不保证全部合并；冲突表达保留时间变化，不承诺自动裁决所有矛盾。
- 模型结构及原句核验能减少失真，但不等于完整语义正确性证明；保存内容仍属于可修订 Scene。
- 不回填之前遗漏的真实聊天，不扩展高级撤回认证，不把这次功能测试视为完整安全审计或 iPhone 用户验收。
- 实际额外费用以供应商账单为准，本轮没有改用新的付费服务。
