# Morrow + Serein：Receiver 认证接线交接（2026-10-28 续）

## 本轮结论

本轮实际完成了 `Trace → source_context → Bridge → HTTP Receiver → author_scene` 的认证接线，并在固定上游、独立合成数据库和真实临时服务进程中跑通。不是只连通接口：成功请求持久保存 Scene、上下文核验回执及依赖边；并发撤回后不能读取旧 Scene，旧索引不能恢复它。

**这仍不是正式原话同步的整体放行。** 非消息对象的远端撤回回执、Hook/工具/媒体的受信读取回执、全部实际语义资源的恢复接管尚未闭合。正式 capture、投递、receiver policy、worker 和自动 Event 继续关闭。本轮没有更换正式程序入口、重启正式服务或升级正式数据库。

开始时 local/main 为 `96e82bad48c0301917436085ca24f7e91e09477b`，fetch 后没有远端差异，工作区干净；正式部署文件树仍是 `bd6c8afcfe1b8600868ad6b93eb8449b194e8633` 且干净。固定 Serein 上游仍为 `ec9f99e8cbc5abf6c024e668760e5cf55884c3dd`，没有更新、安装包或重配模型。

## 真正新增的链路

### 宿主签发与 Receiver 独立核验

- 新增 `context_binding.py`。宿主从同一 SQLite 读事务导出完整可证明依赖图，包括原始消息、有效版本、语义快照哈希、会话、来源事件、摘要与其父清单、独立 owner 声明；不接收模型提供的清单或证据引文。
- `memory_outbox.resolve_source` 复用已有 outbox 和 ACK 状态。在一个宿主读快照中解析所有原话叶节点，不再通过第二个连接混入编辑后的状态。近期记录必须确实出现在图中，不能仅导出几条近期原话假装覆盖整个输入。
- 使用现有私有 bridge 凭据进行标准 HMAC-SHA256、用途分离签名，不复制提供方 API Key。凭证绑定实例、会话、epoch、操作 ID、工具、参数和 30 秒有效期。签名证明宿主身份，**不证明文本是事实、不证明整体系统 certified**。
- Receiver 在真正的 epoch/写事务中重新检查签名、时间、操作绑定、图哈希、节点/对象覆盖、循环、父依赖、unknown 状态，以及原话的消息 ID、会话、事件、有效版本、正文哈希、角色、时间、归档原文和持久回执。
- 已证明摘要可以跨同一私人家庭的私聊会话引用完整原话叶节点；未知旧摘要、未知媒体/工具结果、外部旧记忆不得冒充已证明材料。不是多租户或群聊权限审计结论。
- `serein_source_receiver.register` 的实际 HTTP Scene 写入现在要求完整凭证。原来的只含近期原话引用的 HTTP 请求被拒绝；隔离辅助函数保留旧签名兼容，不将其作为生产网络授权入口。
- 成功事务保存 `morrow_host_context_receipts`、`morrow_context_source_dependencies`，复用 `morrow_document_dependencies` 连接清单节点与 Scene；原话撤回从来源键传播到这些节点及其后代。没有重造 outbox、顺序、ACK 或 epoch 协议。
- 回应含具体 `context_verification` 摘要和 epoch。Bridge 必须精确匹配它，并在回应后再次核对宿主原始清单和隔离水位；否则保留 UNKNOWN，不报告成功、不盲目重复。宿主 `complete` 从未直接变成整体 `certified`。
- 幂等 ID 包含稳定来源/版本哈希与 epoch，不使用每次重建的 Trace UUID；同一输入重试不重复，新有效来源不会复用旧成功。未知结果仍跨回合阻止盲目重复。

现有 `SOURCE_RETRACTION_VERIFIED=False`、receiver capabilities 的 `certified=false` 均未改动。

### 相关读写路径与未知材料的恢复方向

|路径|实际处理|边界|
|---|---|---|
|原始消息及版本|沿用既有捕获、稳定 ID、ACK、来源失效；导出时再验证有效版本|未开启正式捕获|
|已证明摘要及跨会话引用|遍历父清单和全部原话叶节点；不再一概因有摘要拒绝|未知旧摘要不会被升级为完整证据|
|用户显式复核的摘要/记忆|认证 owner 操作产生独立声明类别 `owner_assertion_not_message_quote`|不是用户说过某原话的证据，不批量认证旧材料|
|摘要/记忆被纠正|失效相关清单，隔离未知旧派生缓存；启用捕获模式时阻断外部召回|非消息对象远端撤回尚未完成；不自动清隔离|
|Serein 主观 Scene|可证明上下文走认证写入、CAS 和既有幂等账本；元数据明确为上下文依赖而非事实引文|不修改人格或主观记忆规则；未知上下文仍拒绝写入|
|旧 Morrow 固定/动态记忆写入、后台直写|启用保护时继续由数据库 owner/来源 guard 拦截|尚未把所有后台生成器转换为可用的认证写入|
|Ombre、Hook、工具结果、媒体|保留 unknown 标记和既有记录；不能因接口成功而被认证|受信读取回执仍待补齐；普通聊天保留降级能力|
|通用 MCP 别名|新来源保护模式下拒绝通用 MCP 调用，避免绕过专用 Bridge|只读设备等正常扩展须接入受信读取后再放行；当前正式模式未改变，不影响设备服务|
|无上下文的记忆读取|专用 Serein 只读工具不再因缺少可写上下文而一概拒绝；返回仍不会自动成为可信写入证据|若宿主已有撤回隔离，仍停止外部召回|
|Event、影子数据、索引|继续沿用既有 guard/epoch 和失效图|本轮没有启用、调用或验收实际模型自动 Event|

未知材料并非要求永久删除或永久禁用：旧摘要可用当前有效原话重新生成有父清单的新版本；用户可在现有编辑保存流程显式复核独立摘要/记忆；工具/媒体应补结构化受信读回执。历史原文和旧记忆没有删除，复核也不能把主观理解改名为原话证据。

## 联合备份：新增实际修复和维护检查

继续使用 `joint_memory_backup.py`、原 SQLite backup、原认证加密/恢复格式，没有另建备份体系。

1. 修复真实合成服务联调发现的 WAL 快照问题：读取复制后的 WAL 模式文件会产生新 `-wal/-shm`，导致恢复清单校验失败。只将**新冻结副本**规范为 DELETE 日志模式，源库模式不改；直接加密打包已冻结文件，避免重复复制。源 WAL 模式保持不变有专门断言。
2. assets 支持精确单文件，配置文件不再被迫连同相邻源码/数据库整树备份；声明的资产必须完整进入加密清单，不能被旧通用备份的后缀过滤静默漏掉。
3. 新增只读 `maintenance_status` 与 `controlled_snapshot`：明确列举相关 service/timer，检查停止状态/实例、持久任务、Linux 外部数据库句柄、未知进程访问、数据库身份。未知或活动状态均拒绝；冻结前后维护状态变化则不发布备份。维护证据进入加密清单。
4. 任务检查依据实际固定源码：`pipeline_jobs` 没有 `status`，使用 `output_json` 及父 batch 状态；孤儿未完成任务仍阻断。不是把缺字段当 0。
5. `resume_review` 只比较恢复副本与新获取的对端水位，返回待人工复核状态；新旧不一致停止。即使一致，仍 `release_certified=false`、保留 `recall_blocked`，不启动服务、不覆盖现有实例、不重写配置引用。

低层 `snapshot(... writers_quiesced=True)` 留给受控合成夹具及已有调用；它的布尔参数不是生产认证。正式维护入口必须使用完整资产/写入端清单和 `controlled_snapshot`，仍需验证媒体写入端、配置引用、实例接管；本轮未自动停止正式服务来制造“已停写”证明。

## 仍阻止正式启用的精确问题

1. **非消息依赖撤回尚未获得远端回执。** 已有保守阻断，用户改 owner 记忆或摘要不会继续从宿主正常召回旧外部材料；但必须扩展已有有序撤回通道覆盖这些对象，不能仅解除本地隔离。尚未证明旧签发凭证与“宿主已改、撤回尚未抵达 receiver”窗口的全端原子接管；凭证短有效期和提交后复验不等于跨库事务。
2. **受信读取回执未覆盖全部输入。** Hook、通用工具、媒体和旧外部记忆仍 unknown。新模式暂拒绝 generic MCP，不得以牺牲现有只读设备/扩展能力来宣称上线；应补可信读取/副作用边界，再替代保守阻断。实际自动 Event 模型任务也未单独验收。
3. **七库与准备资源的正式恢复接管仍需证明。** 已有精确资产候选、维护审计和合成四库恢复；必须补 prepared semantic index、scope、OAuth 与配置引用的独立恢复验证，检查所有写入 timer、媒体写入端和活跃对端水位。`ready` 的维护检查也不是整个系统的来源认证。

最短继续入口：本轮 `context_binding`/Receiver 回执已经可用，不必重装服务、重选模型或重做原话签名链。先沿既有 `source_protocol`/epoch 扩展非消息对象撤回及回执，再为 Hook/只读工具引入版本化读取依赖，最后使用已发现的七库资产和 `controlled_snapshot` 完成隔离接管。上述条件未全过，所有正式来源开关保持关闭，自动 Event 不连带启用。
