## 0. M0｜先让谢亦言在域名上正常聊天

**实际开发顺序**：M0（域名 Chat 首通）→ E2（必要部署）→ B2/B3（真实模型、消息保存）→ D（长期记忆）→ F（AI 核心后端）→ 其余模块（全部后移）。E2、B2/B3 只提前当前聊天必需的部分，其他子任务仍在末尾。

**统一执行与验收规则**：
- 每一步必须让用户在浏览器或 iPhone Safari 看到、操作真实功能；只有用户亲自确认才算验收。代码提交、CI、截图、模拟回复和 Codex 报告不算产品验收。
- 禁止把自动化测试套件、验收脚本、假模型回归、隔离证据、覆盖矩阵或形式化报告作为开发前置。
- 复用已确认的 Chat v11 UI，不另造临时聊天框；未实现的按钮明确标识。每步写明打开哪里、看到什么、怎么操作。
- 仅实施当前功能必需的登录、HTTPS、服务端密钥保护和数据持久化。部署、DNS、付费模型及生产数据操作需明确授权，不覆盖现有数据。
- ChatGPT 维护唯一任务书并同步 GitHub `main` 与当前工作分支；Codex 实施；用户实机验收。未同步成功不发新指令。

- [ ] **M0-1｜域名打开 Chat**：在指定域名登录，进入谢亦言私聊，看到并操作已确认的界面与输入框。
- [ ] **M0-2｜接通真实模型**：发送文字，收到真实模型回复；失败有可见提示。
- [ ] **M0-3｜消息持久化**：刷新、重开网页或重新登录后，对话仍在；断网有提示。完成并经用户确认后才算“AI 搬进来”。

**当前动作**：核对现有域名、VPS、Chat v11 与 Chat API，选最短部署路径；取得必要授权后实施 M0-1。
