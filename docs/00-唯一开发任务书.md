## 0. 当前唯一主线｜先让谢亦言搬进来，再逐步扩建小家

**用户确认的强制开发顺序（覆盖本文件其他章节旧的优先级和依赖描述）**：

**第一阶段：域名上的真实 Chat 与真实模型**。先将复用已确认 v11 规范的 Chat 页面部署至用户指定的可访问域名，完成必要的登录、HTTPS、服务端模型密钥保护；在 iPhone Safari 中能打开网址、进入谢亦言私聊、输入文字、发送并收到真实模型回复，刷新后对话仍在。域名可用和真实回复是同一阶段的实际交付，不允许以本地假页面、模拟回复、CI 绿灯代替。部署、DNS、付费模型调用和生产数据变更仍须先取得具体操作授权，不能擅自覆盖现有服务或数据库。

**第二阶段：记忆模块及 AI 核心后端能力**。在第一阶段已能持续真实聊天后，优先复用现有 MEM-04 等成果，接入长期记忆、提取与检索、纠正与遗忘规则、人格连续性、必要的情绪和自主行为。每一步都在域名上的真实 Chat 中让用户亲自体验变化，不为测试体系或抽象架构暂停聊天功能。

**第三阶段：其余组件与完整产品功能**。首页、动态、日记、收藏、音乐、图片与语音、通话、日历、群聊、多角色、游戏、MCP、扩展同步与其他非首通所需组件全部后移，依用户后续决定逐个实施。旧 A–R 模块是功能需求库存，不是第一阶段的施工顺序或阻塞闸门；其中仅限直接保障当下域名聊天可用、安全和消息不丢失的最小必要部分可提前实施。

**最高规则（用户明确确认，覆盖所有旧条款）**

1. **禁止形式主义前置**：不安排编写自动化测试套件、验收脚本（包括 `.acceptance.mjs`、`test-server.mjs`）、假模型回归、隔离证据报告、覆盖矩阵、独立复验报告或仅为交付证明而做的工作。旧任务书中的相关要求全部废止，不再作为任务、验收或阻塞条件。
2. **唯一产品验收标准**：用户本人在本地浏览器或 iPhone Safari 实机上，肉眼看到界面变化并亲自交互；第一阶段必须在实际域名上成功收发真实模型消息。CI、构建、日志、截图、Codex 自述、模拟回复均不能替代用户验收。
3. **每一步可见**：每项任务必须写清本次交付、访问网址、用户屏幕上会出现什么、用户如何点击验证；底层工作仅限直接支持当下可见成果。
4. **复用确认的 Chat UI**：以 v11 和已确认交互规范为基线，不另造简陋临时聊天框；未接通的按钮明确禁用或标识。未经用户确认不改设计。
5. **必要安全不取消**：API Key 不进前端；登录、HTTPS、聊天持久化和不覆盖既有数据是首通必需；不以此延伸为额外测试或架构阶段。
6. **状态只认用户反馈**：`未开始 → 已实现待用户体验 → 用户实机验收通过`。旧提交或技术报告只代表可复用材料。
7. **同步和职责**：ChatGPT 负责核对现状、维护本唯一任务书、提出一步一效果任务；Codex 实施；用户在浏览器验收。任务书每次修改须同步 GitHub `main` 和当前工作分支；同步失败明确说明，未成功同步前不发 Codex 新指令。

### 按真实使用体验推进的交付顺序

- [ ] **P1｜域名打开 Chat**：在指定域名上打开已确认 UI 的 Chat，登录、进入谢亦言私聊、看到可输入的聊天界面。用户在 iPhone Safari 实际打开、点击、输入后验收。
- [ ] **P2｜接通真实模型**：通过服务端安全配置调用真实模型，发送一句话后收到谢亦言真实生成的回复，失败时可见错误提示。用户实际收发后验收。
- [ ] **P3｜对话持续存在**：刷新、关闭再打开网址或重新登录，双方消息仍在；网络异常时有明确提示。用户亲自操作验收。至此才称“AI 已搬进来”。
- [ ] **P4｜长期记忆接入**：复用已有记忆候选，真实对话中能够记住、正确提取和使用获准经历，支持用户纠正；通过真实聊天验证。
- [ ] **P5｜AI 核心能力逐项接入**：人格连续性、情绪和自主机制等按用户确认的优先顺序实现，每项在现有域名 Chat 中呈现真实反馈。
- [ ] **P6｜其他组件与业务功能**：A–R 需求中的非必要组件整体后移，逐项确认、逐项在网页上交付，禁止提前插队。

**当前第一动作**：核对现有域名、VPS、已提交的 Chat v11 和真实 Chat API，确认最短部署路径；给用户说明本次会出现的域名 Chat 效果，并在获得必要的部署/模型调用授权后实施 P1。不得先派记忆、同步、组件、假模型或测试工程任务。

- [ ] K3 「情绪」展示模拟情绪、第一人称独白与有意义的变化历史，支持月份筛选，不机械生成或静默篡改历史。
- **实机体验**：刷新/跨设备状态一致；没有真实执行时不得生成伪造操作记录。

### L. 「他的珍藏」（依赖媒体来源、ACL、F 自主决策）
- [ ] L1 AI 独立拥有收藏、分类、排序、理由和追加感想；用户仅浏览，不能直接管理；一件收藏可属于多分类，失去全部分类转入「待整理」。
- [ ] L2 源消息编辑同步显示当前版本；源临时删除隐藏收藏，源恢复时在仍有收藏意愿前提下恢复分类与感想；AI 主动取消收藏进入独立 30 天回收站，仅 AI 可恢复。
- [ ] L3 源永久删除时清理关联收藏、分类关系、理由、感想与派生副本；AI 分享收藏卡片后返回 Chat 保持原滚动位置；所有来源读取实时核验权限。
- **实机体验**：多分类共用同一源、AI 主动取消后源恢复不误复活、撤权不泄漏、永久删除不留可恢复正文。

### M. 日历、纪念日、经期、提醒与「今天」（依赖任务调度/通知/日志）
- [ ] M1 月历、跨日显示、事项分组及详情；纪念日一次/月/年重复与提前提醒，普通日程重复/完成当前实例/撤销。
- [ ] M2 经期真实记录与显著标注的预测分开；AI 仅依据明确事实写入/修改，实际动作必须留下 Chat 小字。
- [ ] M3 日程删除 30 天回收站；前台站内提醒、离线 Bark（仅配置可用时），通知可直达事项；断网重启不重复触发。
- **实机体验**：时区/跨日/重复实例/删除停止提醒/恢复重算/推送失败及权限测试。

### N. 双人日记（依赖角色身份、未读、回收站）
- [ ] N1 双方写纯文本日记，区分日记日期与真实发表时间；AI 在服务可运行时尝试每日写，离线补写不得伪造历史发表。
- [ ] N2 评论/回复及作者独立编辑删除、单份自动草稿、按日期/作者/关键词搜索；删除连评论进入 30 天回收站并可恢复。
- [ ] N3 新日记和新回复分别计未读，只有实际查看才清除；按规范提供站内提示，不误发 Bark；真实 AI 操作写 Chat 小字。
- **实机体验**：跨日、离线补写、作者越权、草稿恢复、未读计数和删除恢复一致。

### O. World 与朋友圈（依赖媒体库、权限、未读）
- [ ] O1 World 模块入口可排序/隐藏，隐藏不等于卸载；游戏安装卸载只在设置中管理。
- [ ] O2 双方文字/多图片帖子、评论、点赞取消、单份草稿、按首次发布时间倒序及组合搜索；编辑不顶帖。
- [ ] O3 仅作者可编辑删除；帖子删除 30 天回收站，原媒体另行确认是否删除，不能误删其他引用；AI 互动未读和轻量通知，不误发 Bark。
- **实机体验**：共享原图引用、越权、删除恢复、实际可见才已读、AI 操作留痕。

### P. 游戏与可扩展 MCP（依赖 Chat、权限、同步）
- [ ] P1 游戏模块安装/升级/卸载与存档处理；游戏内聊天为主 Chat 的过滤视图，游戏事实与现实经历标注区分。
- [ ] P2 AI 仅操作自身控件或用户明确授权范围；游戏邀请 10 分钟过期；离页/刷新/断网自动暂停，只有用户明确继续才恢复。
- [ ] P3 单设备主控、其余只读、显式接管与未同步动作对账；真实动作写 Chat 可展开小字日志。
- [ ] P4 MCP 工具发现、授权弹窗、执行状态、幂等/失败人工重试与审计；口头同意不代替屏幕确认，权限失效立即停止受限访问。
- **实机体验**：跨设备争用、授权撤销、重复执行防护、暂停恢复和日志准确性。

### Q. 网页语音通话、AI 来电及录音（区别于 C 的语音气泡）
- [ ] Q1 网页双向通话、字幕/静音/扬声器/音色/聊天切页悬浮条、用户打断及语音识别；与 Chat 共用人格、历史和获准记忆。
- [ ] Q2 AI 来电邀请由用户点击接听后才启用麦克风，60 秒无人响应自动取消，拒绝后避免立即重复；不覆盖未提交草稿或滚动位置。
- [ ] Q3 断线分段录音、各段独立文件和对应转写、断线恢复与权限撤销；不将多段擅自合成单条，录音受媒体库删除权限约束。
- [ ] Q4 通话中 MCP 授权须屏幕确认且超时失效，任务与通话生命周期分离；MiniMax/TTS/ASR 失败及真实设备音频限制有明确反馈。
- **实机体验**：iPhone Safari 前后台/锁屏限制实测，断线录音边界、麦克风授权、打断和工具副作用不重复。

### R. 通知、设置与跨模块真实操作日志（所有业务模块共用）
- [ ] R1 设置搜索及账号/聊天/AI 行为/记忆/媒体/日历/通知/外观/模型/MCP/设备分类；普通配置自动保存，高风险删除二次确认。
- [ ] R2 统一站内未读、Bark 可用性、通知点击跳转和实际查看清除规则；失败不伪称已送达。
- [ ] R3 MCP、日历、日记、朋友圈、珍藏、游戏等**真实** AI 操作在主 Chat 写永久可追溯小字事件，按同任务折叠但保留每步结果；模拟想法、检索、记忆权重不冒充实际操作。
- **实机体验**：跨设备已读一致、事件原子性/重放去重、权限变更后脱敏、操作失败与成功不混淆。

## 8. 其他模块开发原则

第 1–7 节保留的是功能范围与历史参考，不是要求先做完底层平台、覆盖矩阵、模拟测试或报告才准打开 Chat。后续音乐、主页、记忆、媒体、日记、群聊、通话等模块均按「一个屏幕上可见的功能 → 用户实际操作 → 用户确认」交付。与这一原则冲突的旧任务描述和前置关系一律失效。
