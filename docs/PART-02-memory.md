### 权限补查（本次实际执行）

对生产接线路径进行代码复核；在内存合成 SQLite 上运行 11 组局部检查，全部通过，0 模型调用、0 生产操作、未新增测试套件：

- 同 AI 跨私聊保持连续；跨 AI 无匹配来源权限的 context 拒绝，不能靠修改 actor 参数取得另一角色私聊。
- 私聊派生记忆和原始经历都不进入群聊；角色亲历的群聊可在其私聊使用，但不会进入另一群。
- 撤权使原目标记忆及生成守卫失效；重新授权不自动复活旧派生版本。注意检索仍可能合法命中其他来源，判断泄漏应核对目标 ID，不以“必须零条”作错误断言。
- 修改来源使旧派生版本失效；软删除隐藏来源和派生记忆，但原始消息保留。
- 实际记忆路由与 AuthService：匿名和设备 Bearer 请求 401；伪造 actor 403；群聊取私聊来源 404；缺 CSRF 或外来 Origin 的修改请求 403。

**不能扩大结论**：上述为代码和隔离运行检查。未在生产流式生成中故意撤权/删来源，未演练所有并发/进程崩溃/跨进程改库；供应商已收到的文本无法撤回。权限为单所有者加 AI/会话/范围边界，不是多用户 ACL。`ChatService.progress`、完成前检查和记忆失效通知为当前守卫接线；近期原始 Chat 上下文没有统一的逐消息输入快照守卫，正式编辑/删除联调时需补齐在途边界。完整永久删除/备份清除与扩展表 Windows 同步仍未完成。本轮未发现需要立即修改代码的已证实越权漏洞。

### 失败状态与事件链路

事件工具现可用 `id:null,parentId:null` 引用已审核记忆提出首卷，后台复核 grant/版本后写 pending，用户确认才生效；修订旧卷须使用真实 event/parent ID 和新证据。API 原子确认，重复确认幂等；来源版本变化的提议不可确认，pending 不作为当前有效事件注入模型。

后台 JSON 结构、明确陈述逐字引用、主观印象字段、来源版本和权限核验仍严格执行；自动整理与自主回顾/选择独立记录。JSON 模式不是证据正确性保证，模型仍可能不合格。失败历史保留，不靠改状态或批量重跑清零；旧 `MEMORY_EVIDENCE_REJECTED` 没有原输出/细分原因，不能追溯具体错误、更不能认定与事件提议有关。新版本细分受控拒绝码，不在日志保存私人模型输出。普通聊天上下文不注入内部置信度/显著性/排序分数；不修改人格。


## 接线

- `memory-next/live/schema.ts`：正式命名空间扩展 `memory_live_*`，扩展账本版本 1；官方 `user_version` 保持 v4，不冒用候选 v5/v6。保留已有 memories、聊天、身份与 outbox。
- `live/store.ts`：复用 MEM-04 的 SourceEvent、MemoryPipeline、parseExtraction；按当前成员／显式授权、现实／游戏／模拟范围过滤，再查来源有效版本、排序。原始经历直接引用有效 Chat 消息，不另复制整份原始聊天。
- `live/runtime.ts`：回复落盘事务中登记后台任务，事务完成后延迟执行。automatic 整理与 autonomous 选择／回顾分别记账；队列、调用状态和用量持久化。重启将执行中任务标 unknown，不自动重复可能计费的调用。
- `chat/service.ts`：近期上下文加预算化记忆资料区；`memory_search` 为模型主动检索，`remember_experience` 排队自主候选，`update_event_thread` 提出有新证据的事件关联。复用同一模型／供应商／密钥；不添加角色人格。工具上下文、调用数和轮次受限。
- `chat/routes.ts`：编辑／软删后登记新版本整理；检索时再次查实际版本／删除／授权状态。永久缺失的来源不可检索，旧修订及事件不能绕过失效检查。
- `MemoryPanel.tsx`：真实 `/chat` 的“长期记忆 · 查看与纠正”，沿用原面板布局，非独立 demo。

## 四类与权限

原始经历为完整有效消息引用；事实与认知为带原文证据的明确陈述；自传记忆和当前印象明确标记主观。原文引述只证明发生过这段发言，不证明客观真相。AI 不能把其他 AI 的发言冒充自己的经历。

当前应用只有一位所有者；同一角色的已授权私聊默认连续，私聊可使用该角色亲历且仍获准的群聊经历。群聊只能读取本群来源，不能取私聊或其他群的记忆。未分配角色的旧会话必须由用户确认记忆归属，不影响原聊天发送，不自动指定谢亦言。

用户纠正有独立修订链并优先于模型旧结论；停用派生记忆不删除原始经历。撤权、源消息删除／版本变动、范围变动使相关派生记录、事件和在途模型资料失效。检索不修改 salience；时间衰减只影响排序，不删除原始记录或把未决事件视为已解决。

事件卷是四类之上的组织结构：保存起因来源、转折来源、状态、未决事项、主观理解和修订。AI 不凭语义相似度自动合并；关联提议须新证据并经用户确认。旧事件理解在来源被纠正后标过时，不注入当前上下文。

## 仅经授权的正式启用

1. 保留当前程序镜像／配置；暂停新的业务写入，等待 queued/running 回复结束，停止唯一后端写入进程。不要修改密钥或原人格／模型环境项。
2. 使用**包含本次代码的新镜像／构建**运行 `node dist/cli.js memory-upgrade --database <已确认主库路径> --backup-dir <已确认备份目录>`。先有 Chat live 扩展及官方 v4。命令执行一致性备份、实际恢复到新副本、在副本演练和旧表校验，再持锁升级主库；中断／失败事务回滚。不要在开发机默认路径上尝试正式迁移。
3. 原路径启动新版，健康检查、登录、正常消息发送先通过；再确认记忆入口状态。默认仅在扩展存在时启用，不在启动／API 中自动建表。可用 `MEMORY_ENABLED=false` 停用记忆，保持聊天。
4. 老会话在记忆入口显式选归属和经历范围，确认授权。新消息成功回复后后台整理。历史补录由“后台整理→整理已授权历史”发起，每次有上限，重复发起幂等；达到预算后可在之后继续或显式重试。
5. 新私聊选择同一个角色，验证回忆、来源、纠正和群聊隔离。未命中不代表事情没发生，可让 AI 主动搜索／继续翻页。iPhone Safari 的最终体验由用户确认。

回退：停止新程序及后台任务，启用保留的旧程序与配置，保留当前数据库的新增消息和扩展表。旧程序忽略命名空间表。**不得用旧快照覆盖出现新消息的数据库**，不删卷、不降级核心账本。恢复文件只允许到不存在的新隔离目标，再做数据对账。

## 可配置项（后端专用）

`MEMORY_ENABLED`、`MEMORY_BATCH_CHARS`、`MEMORY_OUTPUT_TOKENS`、`MEMORY_MAX_CANDIDATES`、`MEMORY_CONTEXT_CHARS`、`MEMORY_AUTO_CONTEXT_CHARS`、`MEMORY_RECALL_LIMIT`、`MEMORY_RELEVANCE_MIN`、`MEMORY_SEARCH_PAGE`、`MEMORY_CALLS_PER_DAY`、`MEMORY_JOB_DELAY_MS`、`MEMORY_TIMEOUT_MS`、`MEMORY_TOOL_ROUNDS`、`MEMORY_TOOL_CALLS`、`MEMORY_HALF_LIFE_DAYS`、`MEMORY_REFLECT_EVERY_TURNS`。默认值见 config.ts，可调整但不修改人设和供应商。输入不合法则关闭记忆，不阻断普通 Chat。后台没有高频 LLM 轮询。

每日调用预算按 UTC 日期统计。实际用量写入 memory_live_calls；主 Chat 工具多轮用量汇总至原 chat_attempts。未知用量保留 null，不伪造费用。没有价格配置，不能把 token 记录称为实际账单。自动整理与主动工具会增加真实模型费用；本次文档收尾不发起真实付费调用；先前经授权的部署核验曾有有限调用，不据 token 数伪造账单。
