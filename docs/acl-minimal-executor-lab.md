# 最小 ACL 执行入口：合成限定实现

日期：2026-10-16。基线方案：acl-governance-minimal-plan.md。本轮只开发并验证新增入口，不重复已验收的106项开发/回归，不涉及真实治理。

## 1. 实现边界

新增 tools/windows-acl-executor-lab.ps1，现有 windows-acl.ps1 与 windows-acl-scope.ps1 不变。没有生产Mode、Plan、Apply、Restore、服务安装或自动提权接口。

入口必须先通过 New-SakieAclSyntheticSession 在不存在的本地FixtureRoot创建新会话。拒绝现存根目录和管理员提升令牌；以当前普通用户SID初始化私有的新根、assets、evidence。会话能力只在创建它的进程内有效，拒绝伪造/未知会话对象。资产只能通过该会话在assets中新建，目录必须是会话已创建父目录，文件内容固定为合成标记，不复制现有文件或真实数据库。路径拒绝越界、ADS、硬链接/重解析点及祖先链接。

原生setter验证内部会话上下文及新Root边界，不提供任意真实路径入口。此限制防止误用，不是抵抗同一用户修改PowerShell源码、篡改内存或直接调用系统API的安全沙箱。

## 2. 封闭范围与审阅

New-SakieAclLabReview 接受逐对象 Path/Profile 与明确禁止路径。仅允许会话注册的资产，重复路径、文件/目录profile不匹配、未知对象全部拒绝。核对真实完整路径集合，而不是只比较数量；同数量的未注册替换也拒绝。

审阅产物 synthetic-review.json 仅是合成会话说明，不是正式生产Plan。其内容包括：

- 当前SID、合成会话/根绑定与工具依赖文件哈希。
- 全部资产原始快照，包括未分配对象、禁止分支及后代；每项路径、Owner、DACL、对象类型、创建时间、内容摘要、大小/修改时间。
- 每个直接对象的profile、目标DACL、保护标志、SID/权限位/继承和传播标志。
- 每个直接目录可能受继承影响的后代，以及明确执行顺序。

审阅文件以UTF-8无BOM写入私有evidence，SHA256与实际文件字节一致。执行要求显式传入该哈希；执行前及逐步执行时复核审阅文件与依赖文件。内存中的审阅JSON在创建后封存，执行不采用外部修改后的预览对象。

## 3. 最小权限profile

| profile | 当前普通用户 | SYSTEM / Administrators |
| --- | --- | --- |
| FileRead | Read、Synchronize | FullControl |
| FileRwd | Read、Write、Delete、Synchronize，不额外授予ExecuteFile | FullControl |
| DirectoryRwd | 当前目录及子目录Modify；单独向文件继承RWD，避免文件获得额外执行权限 | FullControl并保留目录/文件继承 |

各目标均独立保护继承；不更改Owner、Group、SACL，不新增Deny。原始特殊/回调ACE或空DACL拒绝进入审阅。已有普通Deny在原始DACL中可见，只有明确列为目标并审阅替换的合成对象才会被profile覆盖；禁止对象的Deny始终保留。

Owner仍可能拥有Windows隐含WRITE_DAC，profile未宣称隔离账号本人。未来创建的普通数据文件继承RWD；未来身份材料不因目录RWD而自动获得FileRead，必须在后续获准维护中显式列出，不能声称整个配置生命周期已实现。

## 4. 目录影响与执行顺序

本入口不尝试通用传播模拟。审阅时复用只读范围分析：禁止资产若进入直接或潜在影响范围，立即拒绝；每个可能传播影响对象必须在封闭的直接目标清单中，不能漏项。

执行采用路径深度优先、子对象在前的固定顺序：先为批准子对象设置已审阅的受保护DACL，再改目录。每次目录变更前核对所有现存直接子对象已经保护；受保护的禁止分支仅观察、不写入。如果不能建立这一条件就停止，不自动将禁止分支“隔离”或扩大修改范围。

因此本实现验证的是“先逐项隔离批准后代，再修改父目录”的最小策略，而不是放任父级传播后吸收实际结果。对已隔离的现有对象不接受隐式ACL变化。未来新建文件的继承是另行观察，并不回写原封闭清单。

## 5. 执行与审计

Invoke-SakieAclLabExecution 是一次性入口，一次调用即消耗会话执行资格，失败也不能直接复用重试。流程：

1. 核对当前普通SID、审阅哈希、依赖版本及封闭原始快照。
2. 对全部直接/可能受影响对象执行真实内核WRITE_DAC检查，非目标的受保护禁止分支不要求可修改；任一失败零目标修改退出。
3. 在私有evidence独占新建审计文件，写prepared并Flush(true)。
4. 每个对象前重新核对封闭清单、Owner/内容/元数据、未修改对象原DACL、此前对象已审阅目标DACL、审计链/尾部、依赖与全部权限。
5. 持久记录write-intent后才请求原生DACL设置；不写任何资产内容。
6. 后置核对只允许本步目标变成审阅DACL。禁止和其他未修改对象必须维持原DACL；已核验对象与指定profile匹配。将观测摘要写入write-verified，之后才推进已核验列表。
7. 全部对象再次通过检查，成功完成记录落盘后才返回completed。

目标DACL比较保留保护标志、ACL版本及每条Allow ACE的完整字节和重复次数；允许纯Allow换序，并仅忽略Windows的DACL AutoInherited记账位。未修改/禁止对象依旧逐字核对原DACL，不能借此放宽其不变式。

快照可信状态始终来自“原始状态 + 已审阅并已核验的目标DACL列表”，不以观察到的新DACL或外部内容替换基线。

审计含序号、前哈希、完整载荷哈希，每条写入Flush(true)。审计与结果区分已记录意图、已尝试原生步骤、原生返回列表和已核验步骤；原生返回列表在进程内更新，只有后置完成或结果成功落盘后才有对应持久证据，不能据此承诺崩溃窗口无损；存在意图而未核验的对象列入Uncertain，即使本进程还未调用原生设置也不伪造完成。审计失败不继续新步骤；错误结果尽可能另存到新execution-result.json，不修补/覆盖审计原链。

SyntheticFault仅用于新会话中的受控故障注入，结果明确记录故障类型；注入者的变化不属于执行器批准的正常资产操作，均不能触碰旧Root。本轮不提供自动恢复、回滚或重复重试：状态未知时停止留证。

## 7. 残余风险与下一步停止线

- 入口仅能操作本进程创建的新合成会话；真实S1—S7适配、正式生产审阅/执行模式未实现或授权。不能去掉new-root检查就用于真实治理。
- 路径检查、快照及设置之间仍有竞态，没有全程文件身份句柄锁。外部同用户恶意修改不在此机制的防御范围。
- 最小策略要求后代可逐项保护；真实目录的特殊ACE、不可写子项、未明确服务依赖或禁止冲突都会阻塞，不自动扩大权限。
- 审计链有进程内尾锚，但不是签名或持久可信尾锚；审计和DACL不是原子事务。Flush(true)不证明硬件断电恢复，未实现跨进程可信恢复。
- 停止可能留下已经私有化或尚未核验的对象；没有保证全部回滚。恢复需要独立审查和授权，不能照搬旧脚本的自动回滚。
- 本轮不重复符号链接1314场景，不通过提权消除旧跳过项；入口路径校验复用已验收的链接拒绝逻辑。
- 新夹具保留在项目外新子树，继续改变混合根对象清单；旧Plan仍不可用，不清理资产迎合旧计划。
